# Code QA - R10 Analyzer Ingress Security

## Scope

Applied the repository-pinned `tools/code-qa` alignment, meaningful coverage,
and simplicity checks to the active Analyzer ingress security roadmap slice.

## Result

**Aligned and narrowly scoped.** The normalized culture and AST event endpoints
now use an exact, stateless HTTP Basic security chain and the existing Analyser
Import role. Browser sessions cannot authorize machine writes, missing or
invalid credentials fail closed, and an authenticated account without the role
is denied. The authenticated account remains the audit actor without creating
an HTTP session.

The Bridge already supports configured outbound HTTP Basic credentials, so the
slice reuses an existing machine boundary and role. No AMR-specific role,
authentication mechanism, database migration, or client-supplied audit actor
was introduced. Each deployment must configure Bridge with an OpenELIS account
that has the Analyser Import role; provisioning that account is deployment
configuration and is not hardcoded by this feature.

## Meaningful Coverage

- Focused security tests prove missing credentials return 401, invalid
  credentials return 401, a valid account without the role returns 403, and an
  approved account can reach both normalized event handlers without creating a
  session.
- A browser-authenticated session is explicitly rejected by the machine
  boundary, while the existing analyzer reconciliation endpoint remains on the
  interactive application chain.
- The audit utility test was run against the prior implementation first and
  failed because reading the actor created a session. It passes after the
  request-scoped and existing-session-only lookup.
- The registered `core-app` Playwright journey uses a storage-free machine
  client for the event write, then verifies the operator-facing QC review and
  stuck-event reconciliation flows through supported Carbon interactions. It
  uses no arbitrary waits or forced actions.
- Architecture coverage verifies both write controllers require the exact
  existing role. The fixture SQL guard continues to reject application or
  fixture SQL while excluding legitimate Liquibase migration tests.

## Development Path

Running the slice in a fresh isolated worktree exposed two development-tooling
defects. `scripts/dev-stack` now initializes required submodules independently,
repairs only empty broken checkouts, and refuses to force a populated checkout.
The analyzer mock server now attaches its per-analyzer networks as internal
networks so they cannot replace the mock API container's default route on
Docker Desktop. Focused tests cover both repairs, and the full isolated stack
starts and tears down through `scripts/dev-stack`.

The mock-server network repair is reviewed separately in
`DIGI-UW/analyzer-mock-server` PR 41 and is pinned by this branch.

## Simplicity

**Verdict: lean.** The implementation reuses Spring Security Basic auth, the
existing role, the existing Bridge credential support, the normalized event
controllers, the stuck-event workflow, and the shared Playwright fixture
helper. The dedicated chain matches only two write endpoints; it does not
alter unrelated analyzer routes or interactive authorization.

## Known Separate Issues

The Playwright run reports pre-existing analyzer navigation warnings: dynamic
analyzer names are treated as translation identifiers and duplicate React keys
are emitted for some analyzer menu entries. They do not originate in this
security slice and do not affect its acceptance behavior, but they should be
remediated on the analyzer navigation surface.

The current normalized microbiology event contract is proven with the machine
client and operator reconciliation UI. Existing ASTM and HL7 Bridge forwarding
continues to use its established analyzer endpoints; this slice does not claim
to reroute raw analyzer traffic through the normalized microbiology endpoints.
