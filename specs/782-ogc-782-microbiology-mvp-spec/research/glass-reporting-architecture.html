What the profile must understand

Header matching alone is not enough; the profile defines file grammar, record identity, clinical context, and value semantics.

File grammar CSV, workbook sheet, delimiter, quote rules, encoding, header row, decimal convention.
Record shape One isolate or one AST result per row; horizontal or vertical antibiotics; fixed or variable sequence.
Grouping identity Patient, specimen, isolate, and AST keys; repeated columns checked for consistency.
Field semantics Dates, sex, origin, location, specimen, culture purpose, organism, antibiotic, method, measurement, interpretation.
AST grammar Disk zone, MIC, Etest, comparator values such as <=0.25, units, source interpretation, guideline and year.
Code dictionaries Frequency-ranked unknowns; suggested mappings; explicit map, ignore, or block decisions; no silent drops.
Header drift Missing, renamed, duplicated, and newly added columns produce a reviewable profile mismatch.
Preview Raw row, parsed fields, canonical record, warnings, and first records shown before commit.
Run ledger Source checksum, profile version, accepted/quarantined counts, corrections, reruns, and lineage.

Output contracts

Aggregate rows, not line-level isolates; required dimensions use the active WHO GLASS profile.

RIS dataset

  • Country, collection year, national subset
  • Specimen, pathogen, antimicrobial
  • Sex, age group, infection origin
  • Counts R, I, S
  • AST not reported and performed without interpretation

SAMPLE dataset

  • Country, collection year, national subset
  • Specimen, sex, age group, infection origin
  • Patients sampled for bacterial isolation
  • GLASS-pathogen positive
  • Non-GLASS positive and negative/no-growth

Architecture decisions

Recommended defaults separate confirmed product direction from decisions that need explicit validation.

Application boundaryRecommended
Separate national reporting application consuming multiple laboratories; OpenELIS remains a facility data producer.
Prevents GLASS-specific aggregation and national identity logic from distorting routine LIS workflows.
Open profile formatRecommended
UI-authored, versioned JSON or YAML profile with parser settings, field rules, dictionaries, validation policy, and tests.
Exportable and reviewable; not a WHONET .cfg clone.
Clinical interpretationRecommended
Preserve reviewed site interpretation. When only raw AST exists, compute from explicitly selected CLSI/EUCAST version; retain both source and computed values.
No silent standard mixing; direct CLSI use requires licensed distribution or site-supplied data.
Canonical terminologyRecommended
Internal stable concepts with aliases for local, WHO GLASS, FHIR terminology, and optional WHONET codes.
Avoids replacing one tool-specific coupling with another brittle transport coupling.
National patient matchingNeeds design
Choose a privacy-preserving, stable cross-site patient key and define collision/absence handling.
Without it, national repeat-isolate selection cannot be correct across facilities.
Current GLASS contractNeeds source fixture
Obtain the active WHO templates/data dictionary and freeze them as a versioned compiler profile with official validation examples.
Do not infer current file columns from old WHONET output or mock labels.
Replacement scopeProposed boundary
Eliminate WHONET from the GLASS submission path; preserve optional compatibility imports. Local outbreak analytics and every WHONET analysis screen are separate product scope.
Keeps the deliverable testable while removing operational dependence for national reporting.

Manageable build order

Each slice has a visible, testable exit condition.

  1. Freeze external contractsAcquire current WHO RIS/SAMPLE templates, representative FHIR bundles, real wide/long site files, a WHONET isolate file, and authorized CLSI/EUCAST fixtures. Exit: golden inputs and expected outputs are review-approved.
  2. Canonical model + lineageImplement specimens, culture outcomes, isolates, AST, terminology aliases, import runs, and source pointers. Exit: positives, negatives, amendments, and multiple isolates round-trip without loss.
  3. Open mapping profileDefine portable profile schema and execution engine. Exit: same file + profile produces identical canonical records; incompatible headers block before import.
  4. CSV / Excel workbenchAdd sheet/header/delimiter/encoding, wide/long AST, code frequencies, preview, map/ignore/block, quarantine, and rerun. Exit: a non-OpenELIS site completes a recurring import without WHONET.
  5. Structured OpenELIS FHIRPublish culture, no growth, isolate, and AST observations through existing transport. Exit: national ingest reconstructs the same canonical record as the facility case.
  6. Standards interpretation serviceLoad versioned CLSI/EUCAST data legally, retain raw/source/computed values, and explain every result. Exit: a published conformance set matches expected S/I/R behavior.
  7. National scope + repeat logicApply period, subset, specimen/pathogen eligibility, patient matching, and current GLASS repeat policy once. Exit: cross-site repeats and no-growth denominators pass worked examples.
  8. RIS + SAMPLE compilerGenerate versioned outputs, quality report, traceable counts, review sign-off, and run history. Exit: official validator accepts both files and every aggregate cell traces to inputs.
  9. Operational qualificationAccessibility, performance, security, backup/recovery, mapping governance, staged rollout, and UAT. Exit: representative national volume and failure recovery are demonstrated.
