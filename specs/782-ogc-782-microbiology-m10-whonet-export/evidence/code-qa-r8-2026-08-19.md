# R8 WHONET Specimen Mapping Code-QA

## Verdict

**Lean and aligned for the R8 slice.** The implementation reuses the existing
`TypeOfSample.whonetCode`, Sample Type administration, WHONET preview pipeline,
and canonical return URL. It adds no schema, parallel mapping catalog, fixture
SQL, fixed persisted identifiers, browser sleeps, or forced interactions.

## Alignment

| Finding | Classification | Resolution |
|---|---|---|
| Export used the local sample-type description instead of its WHONET code. | Code defect | Preview and CSV now project `TypeOfSample.whonetCode`; unmapped specimen rows are excluded with one scoped warning. |
| The repo spec treated several user-visible M-09 controls as technical suggestions. | Spec/roadmap drift | The spec now distinguishes non-binding routes/storage from binding functional behavior. `tasks.md` enumerates export selection, advanced de-duplication, remaining vocabularies, output qualification, history, and delivery as separate future slices. |
| The standardized M4 demo assumed specimen mapping was already complete. | Evidence drift | The demo now records the blocked preview, exact Sample Type repair, return to the same preview, remaining organism gap, and generated CSV. |
| Two service-created M4 scenarios initially reused one sample-type abbreviation; the first uniqueness fix then exceeded the real 10-character column. | Fixture/test defect | The fixture now derives a distinct 10-character abbreviation from each scenario key. Unit coverage proves two scenarios differ, and a persistence test provisions both through the real schema. |

The compact implementation matches the authoritative M-09 painless workflow:
open, Preview, repair scoped gaps, and Generate. The broader M-09 mock remains
future functional scope rather than being mistaken for completed behavior.

## Meaningful Coverage

- `MicroWhonetDatasetServiceTest` is the load-bearing inversion guard. It fails
  against the prior behavior, which exported the local specimen label and kept
  rows whose sample type had no WHONET code.
- `MicrobiologyUatScenarioServiceTest` proves the M4 fixture creates a dedicated
  unmapped sample type through services, gives independent scenarios distinct
  schema-valid abbreviations, and leaves ordinary microbiology fixtures mapped.
- `MicroWhonetPersistenceIntegrationTest` provisions two independent M4
  scenarios through the real service and database stack, preventing mock-only
  fixture checks from missing schema-width or uniqueness constraints.
- `SampleTypeManagementRestControllerSecurityTest` prevents WHONET from
  reappearing as a competing generic terminology source.
- Component and route tests prove exact repair URL composition, safe local
  return handling, field focus, persistence, and the explicit return affordance.
- The registered `core-app` Playwright journey proves configured navigation,
  canonical preview state, blocked generation, repair/save/return, retained
  partial warning, and CSV rows containing `SPECIMEN_TYPE=BLD`.

## Simplicity

- Kept on purpose: a scenario-specific M4 sample type is required so the repair
  story is deterministic without breaking the mapped sample type shared by
  other service-created fixtures.
- Kept on purpose: the repair route validates a local WHONET return target so
  the admin page cannot become an open redirect.
- Removed: WHONET as a generic terminology source. The dedicated sample-type
  field is the single owner.
- No speculative abstraction or new persistence layer was added.
