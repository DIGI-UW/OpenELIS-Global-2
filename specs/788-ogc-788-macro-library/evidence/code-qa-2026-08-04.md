## Reusable Boundaries

- `MacroTextArea` is the shared controlled Carbon adapter for all supported
  narrative fields; microbiology passes context and existing form state only.
- `macroTextEngine` owns pure token detection, filtering, and replacement.
- `TextMacroService` owns the frontend API boundary.
- `queryState`, `useMacroLibraryQuery`, `textMacroConfig`, and
  `MacroEditorModal` isolate URL, data, controlled vocabulary, and editor
  concerns from the page composition.
- The backend keeps entity, DAO, transactional service, DTO, runtime controller,
  and admin controller responsibilities separate under the repository's
  required layered architecture.
- `text-macro.ts` provides one Playwright interaction vocabulary for admin and
  clinical journeys.

The dedicated model and service/controller split are intentional complexity:
the feature is cross-cutting, audit-sensitive, and paged. Reusing `Dictionary`
or persisted clinical `Note` records would merge incompatible semantics. The
DAO uses separate page/count queries, and the service compiles DTOs inside the
transaction; collection join-fetch pagination is intentionally avoided.
