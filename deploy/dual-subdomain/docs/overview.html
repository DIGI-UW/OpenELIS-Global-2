OpenELIS · UAT Review Harness

Author once. Review anywhere. Triage in Claude.

A self-hosted loop for reviewing in-progress OpenELIS features. Checklists are authored once in Grist — by people or by agents — served live into a review overlay on each demo site, and returned as reports that Claude turns into Jira issues.

The review overlay is the hinge: it turns authored checklist steps into captured feedback. An edit in Grist (by anyone) shows up in the overlay within ~30 seconds — no publish step.

Do it yourself

Author or edit a checklist

Pick the surface that fits you — both write to the same Grist doc.

  1. As a person: sign in at grist.openelis-global.org and edit the UAT_Steps table like a spreadsheet — one row per step.
  2. As an agent (Claude Code): connect the native Grist MCP once, then ask in plain language (“add a step to the amr checklist covering X”).
# connect the authoring MCP (CLI)
claude mcp add --transport http grist \
  https://grist.openelis-global.org/api/mcp \
  --header "Authorization: Bearer <grist-api-key>"

Review & give feedback

No account needed — the overlay rides on the demo site.

  1. Open a demo site (amr or analyzers) and click Review in the corner.
  2. Work the checklist — mark each step pass / fail / n-a and leave notes where something’s off.
  3. Hit Download review report — you get a Markdown + JSON pair.
  4. Paste the Markdown into Claude; it triages your findings into Jira/GitHub items.

Where this lives

The harness is a self-contained ~two-dozen-file unit (router · Grist + MCP · review overlay · deploy scripts). It orchestrates OpenELIS builds at deploy time but is not application code — the plan is to lift it into its own repository so it can iterate independently of the OpenELIS-Global-2 codebase and its CI.
